# Channel distribution

[简体中文](README.md) · **English** · [Back to collection](../README.en.md)

Skill sources are maintained only in `skills/`. Every channel's package is generated by `build.py` from the same sources:

| Channel | Artifact | Method |
| --- | --- | --- |
| Claude Code / Codex / ZCode | The repository itself (`.claude-plugin/`, `.agents/plugins/`) and `zcode/` plugin bundle | Takes effect on push; users install from the repository marketplace or Release |
| npx skills / skills.sh / SkillsMP | Public GitHub repository | Indexed automatically |
| GitHub Release | Collection ZIP + per-platform packages + `SHA256SUMS` | `gh release create` |
| Tencent SkillHub | `skillhub/<skill-name>/` directories | `skillhub publish` |
| WorkBuddy | `workbuddy/<skill-name>-<version>.zip` | Web upload on the open platform |

## Versioning and packaging

The version number is recorded in `manifest.json`; also update the root `plugin.json`, `.claude-plugin/plugin.json`, the ZCode shell `.zcode-plugin/plugin.json`, and the server and panel version markers. These versions must match (`check` verifies this). All ZCode shell files must exist and be tracked by Git; missing files fail the build. Skill names stay the same; the Tencent `slug` defaults to the skill name, so confirm it is not taken before the first publication.

Run from the repository root; only Python 3.10+ and Git are needed:

```bash
python distribution/build.py check
python -m unittest discover -s distribution/tests -v
python distribution/build.py build --out dist/<version>
```

A few rules and the reasons behind them:

- **Only files tracked by Git are packaged.** New runtime files must be `git add`ed before building; otherwise the build reports them as missing instead of silently leaving them out.
- **Skill packages contain only the files needed at runtime**: the root `SKILL.md`, README, LICENSE and requirements, plus `scripts/`, `references/` and `assets/`. Tests, examples, development docs and the ROADMAP stay in the repository; if nested tests, caches, `_selftest.py`, credentials or local dependencies end up in the runtime directory, the check fails.
- **Existing output is not overwritten.** The build refuses to run if the output directory already exists; use a new directory to rebuild.
- **Static checks**: verify the standard Agent Skills frontmatter, the three version numbers, local Markdown links in `SKILL.md` and `references/`, and `references/*.md` paths in backticks. Link targets must exist and be packed into the same skill package; online links, examples in code blocks and Obsidian wikilinks are not checked.
- **Size budget**: `packageBudget` in `manifest.json` is a limit set by this project: at most 200 runtime files and at most 5 MiB uncompressed for the collection. Tencent's web uploader has a hard limit of 200 files and 10 MB per package; this project uses the same file count and leaves headroom on size. `check` prints file counts and byte sizes for the collection and each skill, and `build` prints each ZIP's file count and its size before and after compression.

## Repository development layout

Runtime sources are in `skills/<skill-name>/`; development assets are collected at the repository root:

- `tests/sanmu-doc2md/`, `tests/sanmu-paper-reader/`, `tests/sanmu-paper-search/`: offline tests; the doc2md entry point is `tests/sanmu-doc2md/_selftest.py`;
- `examples/sanmu-doc2md/`: original examples, PDFs, screenshots, `RESULTS.md` and `RESEARCH-VALIDATION.md`;
- `docs/development/sanmu-doc2md/ROADMAP.md`: future development plans;
- `docs/showcases/sanmu-paper-reader/images/`: reader showcase screenshots;
- `distribution/tests/`: packaging regression tests.

```bash
python tests/sanmu-doc2md/_selftest.py
python -m unittest discover -s tests/sanmu-paper-reader -v
python -m unittest discover -s tests/sanmu-paper-search -v
node --test tests/zcode-paper-search/test_mcp_server.mjs tests/zcode-paper-search/test_panel.mjs
```

Examples and showcase images are only for browsing the repository and development validation; in an installed skill, all runtime links should point to resources inside the package.

## Build artifacts

Under `dist/<version>/`:

| File | Purpose |
| --- | --- |
| `sanmu-skills-<version>.zip` | General collection package: three skills + root `plugin.json` + Claude plugin manifest + licenses; can also serve as the package to submit to the OpenAI public plugin directory |
| `skillhub/<skill-name>/` | Directories passed to `skillhub publish` |
| `skillhub/<skill-name>-<version>.zip` | Archives with the same content as the directories above, with `SKILL.md` at the root |
| `workbuddy/<skill-name>-<version>.zip` | WorkBuddy skill packages, with `SKILL.md` at the root |
| `zcode/sanmu-paper-search-zcode-plugin-<version>.zip` | ZCode Desktop side-panel plugin package for `sanmu-paper-search` (assembled from `distribution/zcode/` and `skills/sanmu-paper-search/`) |
| `SHA256SUMS` | SHA-256 of the 8 ZIPs above, LF line endings |

**Platform-specific metadata is applied only at build time.** The source `SKILL.md` stays in the standard format, and the body and resources are identical across channels:

- SkillHub: `slug`, `displayName`, `version`, `summary`, `license`;
- WorkBuddy: `display_name`, `display_name_en`, `description_zh`, `description_en`, `version`, `author`.

The SkillHub display name is set in `manifest.json` as `displayName`; WorkBuddy uses a separate `workbuddyName` identifier and `workbuddyDisplayName` / `workbuddyDisplayNameEn` display names. Summaries are shared as `summary` / `summaryEn`, and the author is set in the top-level `author`.

Both platforms reject files without an extension, so the `skillhub/` and `workbuddy/` packages do not include `LICENSE`; license information is provided by the frontmatter and the collection package.

## Claude Code and Codex

```bash
claude plugin validate .claude-plugin/marketplace.json --strict
claude plugin validate .claude-plugin/plugin.json --strict
```

The Codex repository marketplace is `.agents/plugins/marketplace.json`, which points to the root plugin with the local source `./`. You can add the local marketplace in a separate test configuration and then run `codex plugin add sanmu-skills@sanmu-skills` to verify.

A self-hosted GitHub marketplace is not the same as being listed in Anthropic's or OpenAI's official directory. The OpenAI public directory requires a separate [submission through the developer platform](https://developers.openai.com/plugins/deploy/submission): upload the ZIP, address the check results, then wait for review.

## GitHub Release

Files on the Release page are flat, without `skillhub/` or `workbuddy/` subdirectories, and the packages for the two platforms have the same names. So when uploading, add a platform suffix to the WorkBuddy packages, and generate a checksum file that matches the flat file names:

```bash
V=<version>; D=dist/$V; R=$D/release; mkdir $R
cp $D/sanmu-skills-$V.zip $D/skillhub/*.zip $D/zcode/*.zip $R/
for f in $D/workbuddy/*.zip; do cp "$f" "$R/$(basename "$f" .zip)-workbuddy.zip"; done
(cd $R && sha256sum *.zip > SHA256SUMS)
gh release create v$V $R/* --title "sanmu-skills v$V" --notes-file <release-notes.md>
```

## Tencent SkillHub

All three skills are published:

| Skill | slug |
| --- | --- |
| sanmu-doc2md | `sanmu-doc2md` |
| sanmu-paper-reader | `sanmu-paper-reader` |
| sanmu-paper-search | `sanmu-paper-search` |

Upload the build artifacts, not the `skills/<skill-name>/` source directories: `node_modules/` and `__pycache__/` in the source directory push doc2md over the 200-file limit, and the other skills' `.pyc` files get skipped. Later versions are updated under "Version history" in the console, with the same slug.

Before publishing with an API token, complete identity verification and configuration according to the [official tutorial](https://skillhub.cn/tutorials). The official Windows tutorial uses WSL. Do not put the token in source code, command examples or commit history.

```bash
skillhub auth whoami
skillhub publish ./dist/<version>/skillhub/sanmu-doc2md --dry-run
skillhub publish ./dist/<version>/skillhub/sanmu-paper-reader --dry-run
skillhub publish ./dist/<version>/skillhub/sanmu-paper-search --dry-run
```

After the dry run passes, remove `--dry-run`, add `--changelog "<version>: release notes"`, and submit each one. A `pending_review` response only means it was submitted, not that it is publicly listed; go by what the console shows.

## WorkBuddy

On the [WorkBuddy open platform](https://open.workbuddy.cn), choose **发布管理 → 技能** (Publishing → Skills) in the left sidebar and upload `workbuddy/<skill-name>-<version>.zip`, one upload per skill.

- **Do not use the "专家" (Experts) entry.** An "Expert" is an agent role package that requires `.codebuddy-plugin/plugin.json`, `agents/*.md`, a 512×512 avatar and Chinese and English display text, a completely different structure; uploading a skill package there fails with "未找到 .codebuddy-plugin/plugin.json" (.codebuddy-plugin/plugin.json not found).
- Required fields for skill packages follow the [official skill documentation](https://open.workbuddy.cn/docs/skill): `description`, `description_zh`, `description_en`, `version`, `author`. Display names are not marked as required, but parsing actually fails without them, so they are written too.
- Paid asset names accept Chinese characters, English letters, digits, `-` and `_`; spaces and middle dots are not allowed. The build validates both display names. The current Chinese names are “三木学术文档转Markdown”, “三木文献精读” and “三木文献检索”. The console parses `display_name` from the package into a read-only field, so renaming requires uploading a new ZIP.
- All three paid skills are created as new records using “创建” (Create), with WorkBuddy identifiers `sanmu-doc2md-paid`, `sanmu-paper-reader-paid` and `sanmu-paper-search-paid`. Previously published records stay unlisted. In the tested console, an existing free record's update form has no payment selector, while creating with its old identifier is rejected as a duplicate. Channel-specific identifiers avoid that conflict; source and SkillHub identifiers stay the same.
- `workbuddyVersion` is currently `1.6.9`, matching the collection version `1.6.9`. If omitted, it defaults to the collection version. When updating an existing record, the platform requires a version greater than its latest one.
- All three new skills use monthly billing at CNY `3` per month. Pricing is configured in the console, not in the ZIP. After saving, verify “按月付费·3元/月” on the confirmation page before submitting for review.
- If parsing fails, first check against "技能基础结构" (basic skill structure) in the official documentation; if you still cannot find the cause, email openworkbuddy@tencent.com.

## SkillsMP and skills.sh

Keep the `agent-skills` GitHub topic, and add `claude-skills` or `claude-code-skill` as listed in the SkillsMP FAQ. SkillsMP indexes public repositories automatically; after it syncs, check the actual detail page. Setting the topic is not proof of being listed.

The skills.sh [collection page](https://skills.sh/luffysolution-svg/sanmu-skills) updates automatically from `npx skills add` installs and anonymous telemetry; no separate npm package needs to be published.
