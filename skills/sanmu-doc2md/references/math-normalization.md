# 公式归一化规则

OCR（尤其 MinerU）输出的 LaTeX 通常"语法上能编译"，但直接放进 Markdown 会有几类固定问题。下面每条都来自实际踩坑，附真实的前后对照。

`scripts/normalize_math.py` 只自动处理保守、明确的语法问题。涉及式号、化学结构或符号含义的改动，要回看原页后通过 `--repairs` 应用：脚本看不到原页，猜错了就是悄悄改了科学含义。

## 目录

- 目标格式
- 规则 1–3：中文、嵌套 `\text{}`、全角标点
- 规则 4–5：粘进公式的正文、跨界括号
- 规则 6–8：`\rm` 简写、标题公式、图片 alt
- 规则 9–10：命令粘连、化学式移出 `\text{}`
- 规则 11–12：重复式号、环状结构降级为原图
- 规则 13–15：配合物物态、不等号、解释性方括号
- 校验

## 目标格式

- 行内：`$E = mc^2$`
- 独立：`$$` 单独成行，公式内容一行，`$$` 单独成行
- 保留原式号：`\tag{1-6}`（正文常引用"由式（1-6）可知"，去掉就对不上了）

Obsidian 使用 MathJax；本工具的 KaTeX 编译与离线预览用于语法预检，不能代表 Obsidian 的解析和显示结果。先记录目标客户端及数学引擎，再运行下文检查，并在实际客户端核验。编译成功只说明公式被当前引擎接受，不证明符号、式号或科学含义与原页一致。

## 规则 1：中文放进 `\text{}` 而不是 `\mathrm{}`

**问题**：OCR 会把公式里的中文词用 `\mathrm{}` 包起来。KaTeX 对 `\mathrm{中文}` 会输出 `No character metrics for 'X' in style 'Main-Regular'` 告警，且渲染中文字符间距不齐。

```latex
% 归一化前（OCR 输出）
\eta = \frac {\mathrm{连续} X \mathrm{射线总强度}}{X \mathrm{射线管功率}} = K Z V

% 归一化后
\eta = \frac {\text{连续} X \text{射线总强度}}{X \text{射线管功率}} = K Z V
```

同理，裸露的中文（没被任何命令包住）也要包进 `\text{}`：

```latex
% 前
h v _ {K \alpha} = W _ {K} - W _ {L} 或 h v _ {K} = h v _ {L}

% 后（"或" 是中文，需包起来）
h v _ {K \alpha} = W _ {K} - W _ {L} \text{或} h v _ {K} = h v _ {L}
```

## 规则 2：展平嵌套的 `\text{}`

**问题**：OCR 重排时会产生 `\text{\text{...}}` 嵌套，KaTeX 里行为不确定。

```latex
% 前
F = \frac {A _ {b}}{A _ {e}} = \frac {\text {\text{一个晶胞中所有原子散射波的合成振幅}}}{\text {\text{一个电子的散射振幅}}}

% 后
F = \frac {A _ {b}}{A _ {e}} = \frac {\text{一个晶胞中所有原子散射波的合成振幅}}{\text{一个电子的散射振幅}}
```

## 规则 3：公式内的全角标点换成半角

**问题**：中文输入法可能在数学模式中产生全角括号 `（）`、逗号 `，`、分号 `；`，造成间距差异，也可能被简单的 ASCII 括号检查遗漏。先核对原页；仅对数学标点做必要归一化，保留 `\text{}` 中有意义的中文标点。

```latex
% 前
\alpha = f ( \mathrm{或} r _ {n} （Z _ {e}） )

% 后
\alpha = f ( \text{或} r _ {n} (Z _ {e}) )
```

归一化后可检查括号，生成回源复核候选。圆括号、方括号也可能表示半开区间、矩阵边界或跨正文分组，不能凭计数自动增删或移动。

## 规则 4：公式前后粘进来的正文要拆回正文

**问题**：OCR 有时把公式前面的一小段正文（含括号的）一起圈进公式块，导致公式开头挂着一截中文、括号还不配平。

```latex
% 前（"和像差（主要是球差" 是正文，被粘进了公式）
$$
\text{和像差（主要是球差} \varDelta r _ {s} = \frac {1}{4} C _ {s} \alpha^ {3}) 。
$$

% 后（正文回到正文，公式干净）
和像差（主要是球差
$$
\varDelta r _ {s} = \frac {1}{4} C _ {s} \alpha^ {3}
$$
）。
```

候选定位：若公式括号不配平且开头为 `\text{中文...}`，可检查前缀是否来自正文；配平只帮助定位疑点。切点、括号归属和公式范围要对照原页及相邻正文确认后，再通过 `--repairs` 应用。

## 规则 5：行内公式跨界括号

**问题**：源文档里括号一半在正文、一半在公式内的写法，OCR 可能照抄。先核对原页确定是正文分组还是数学分组；下面展示的是已确认属于正文的情况，别仅凭括号计数照搬。

```markdown
% 前（后括号在公式里，公式自身不配平）
如果入射角与反射角相等，则 $\delta = a$ （ $\cos \theta - \cos \theta) = 0$ 。

% 后（括号还给正文，公式干净）
如果入射角与反射角相等，则 $\delta = a$ （ $\cos \theta - \cos \theta$） = 0 。
```

## 规则 6：`\rm` / `\it` 等简写正常化

OCR 会输出 `\rm`、`\it` 这类旧式简写。保留字形语义及作用域，分别用 `\mathrm{}`、`\mathit{}`；斜体和直立体含义不同（变量与单位、算符），不要统一改成直立体：

```latex
% 前
d _ {\rm hkl}

% 后
d _ {\mathrm{hkl}}
```

## 规则 7：标题公式保留定界符，纯文本位置使用等义 Unicode

Markdown 标题默认保留行内公式，例如 `### 6.3.2 $\mathrm{R}^2$ 比值规律对比法`。目录、大纲、搜索结果和不同宿主对标题公式的显示能力不同，需要在目标客户端核验；但不要因此剥掉定界符，留下裸命令或下划线。化学式案例见本规则末尾的对照。

仅在目标位置要求纯文本（如图片 alt、纯文本大纲），或用户明确选择纯文本标题且表达可等义转换时，使用 Unicode：

```markdown
<!-- 含裸 LaTeX 的标题应补齐定界符 -->
### 6.3.2 $\mathrm{R}^2$ 比值规律对比法

<!-- 纯文本标题的等义表达 -->
### 6.3.2 R² 比值规律对比法
```

可等义转换的常见字符：`\mathrm{X}` → `X`、`^2` → `²`、`^3` → `³`、`\alpha` → `α`、`\theta` → `θ`、`\psi` → `ψ`、`\circ` → `°`、`\times` → `×`。复杂分式、矩阵或无法完整表达的上下标保留公式，压成纯文本会丢信息。

### 标题化学式案例（规则 7 的补充）

**问题**：常见做法是对章节标题直接调用 `plain_text()`，剔掉 `$` 和 `{}` 却留下裸下划线 `_2`，化学式就变成了 `CO_2`、`N_2`、`H_2-TPR`。这既难看，又容易和同一行的其他下划线配对，被 Markdown 渲染成斜体。

**做法**：
- Markdown 标题（`#` ~ `######`）默认保留行内公式，并在目标客户端核验。标题中含有的分子式与数学符号保留标准 LaTeX 语法（如 `### 1.3.2 $\mathrm{CO}_2$ 辅助乙烷脱氢`）；
- 若在纯文本大纲或图片 `alt` 中强制降级，下标转为 Unicode 字符（如 `CO₂`），不留裸下划线。

```markdown
<!-- 错误：剥掉定界符后留下裸下划线 -->
### 1.3.2 CO_2 辅助乙烷脱氢
### 3.4.5 程序升温脱附（ NH_3 -TPD， CO_2 -TPD）

<!-- 正确：保持规范行内 LaTeX 公式渲染 -->
### 1.3.2 $\mathrm{CO}_2$ 辅助乙烷脱氢
### 3.4.5 程序升温脱附（ $\mathrm{NH}_3$ -TPD， $\mathrm{CO}_2$ -TPD）
```

## 规则 8：图片 alt 使用纯文本，独立图注保留公式

**问题**：图注被直接塞入图片 alt 时，复杂定界符、方括号与转义可能在特定渲染链中破坏图片语法，且 alt 通常不渲染数学。这是实际遇到过的案例，但并非所有含 `$` 或 `\` 的 alt 都会出错，以浏览器实测为准。

```markdown
% 前（含公式的 alt，在实际渲染中排查）
![图4-1 $\theta$ -sin $\theta$ 关系曲线](images/ch04/xxx.png)

% 后
![图4-1 θ -sin θ 关系曲线](images/ch04/xxx.png)
```

图片 alt 使用可等义表达的纯文本并转义方括号；复杂公式另放在图片下方的独立图注段落中，保留 `$...$`。Markdown 标题按规则 7 处理。

## 规则 9：反斜杠命令与紧随物种符号粘连分离

**问题**：OCR 经常将操作符命令与物理量/化学符号连写，缺少空格，导致 LaTeX 将其视作不存在的未定义宏。

```latex
% 前（非法宏 \vertHg 和 \cdotkg）
\frac{\varphi_{\text{Cl}^-\vertHg_2Cl_2}(298\text{ K})}{\text{V}}
\mathrm{CuSO_4(1mol\cdotkg^{-1})}

% 后（补齐命令分隔空格）
\frac{\varphi_{\text{Cl}^-\vert Hg_2Cl_2}(298\text{ K})}{\text{V}}
\mathrm{CuSO_4(1mol\cdot kg^{-1})}
```

其他实际遇到过的例子：`\vertz` → `\vert z`、`\vertj` → `\vert j`。常见受影响命令：`\vert`、`\cdot`、`\times`、`\pm`、`\partial`、`\nabla`、`\sum` 等。

## 规则 10：化学式移出 `\text{}` 避免非法下标

**问题**：OCR 把电池电解液、电极材料或化学反应式放进 `\text{...}` 中，在文本模式下出现未闭合的下划线 `_` 会直接导致 KaTeX 语法解析中断（`Expected 'EOF', got '_'`）。

```latex
% 前
\text{NH_4Cl/ZnCl_2/MnO_2/湿C粉/NH_4Cl}

% 后（化学式放入 \mathrm，仅中文汉字放入 \text）
\mathrm{NH_4Cl/ZnCl_2/MnO_2/}\text{湿C粉}\mathrm{/NH_4Cl}
```

## 规则 11：回源确认重复式号与损坏脚注标记

**问题**：OCR 时常产生双重 `\tag`，或将原书式号右上角的脚注上标（如 `(12.45)¹`）误识成跨界的未闭合花括号。保留哪个编号要核对原页确定；以下是已确认的修复示例。

```latex
% 前
E = mc^2 \tag{7}\tag{12.26}
K_c = \frac{f^{\neq}}{f_{\mathrm{A}}} \tag{12.45) $ ^{①} \}

% 后
E = mc^2 \tag{12.26}
K_c = \frac{f^{\neq}}{f_{\mathrm{A}}} \tag*{(12.45)$^{\text{①}}$}
```

## 规则 12：复杂环状分子与化学键结构的原图降级

**问题**：OCR 试图用 `\begin{array}` 与 `\backslash` 拼凑三角形或环状化学键（如环丙烷异构化反应），导致公式无法解析且严重失真。

**原则**：对当前渲染环境无法准确表达的复杂二维反应历程、空间环状骨架，使用源 PDF 局域高清裁切保留空间关系，并对照原页核验，不强行拼凑字符。

## 规则 13：化学配离子状态与 CommonMark 语法消歧

**问题**：配合物配离子后紧接物态（如 `[Fe(CN)6](aq)`、`[Co(NH3)6](s)`），在 Markdown 解析中会被误判为超链接语法 `[text](url)`，导致解析器试图寻找本地名为 `aq` 的文件并报失效链接错误。

```latex
% 前（在正文中裸露，易被 CommonMark 误判为 [Fe(CN)6] 链接指向 aq）
Pt(s)|K₃[Fe(CN)₆](aq), K₄[Fe(CN)₆](aq)||...

% 后（放入数学化学环境，或在方括号与物态之间添加空格消歧）
\mathrm{Pt(s)|K_3[Fe(CN)_6](aq), K_4[Fe(CN)_6](aq)||...}
```

## 规则 14：远小于/远大于与表格公式不等号保护

**问题**：物理化学中频繁出现的极限条件（如高分子恢复力条件 $x \ll R_c$）在 OCR 中常识别为 `<<` 或 `>>`。在 HTML 表格中，`<td> $x<<R_c$ </td>` 很容易被 BeautifulSoup 等解析器当成未闭合标签 `<r_c>` 吞掉，导致公式断裂、定界符失配。

**做法**：
- 在进入 HTML 解析前，公式内的 `<` 与 `>` 须预先做 HTML 实体化安全转义；
- 在数学模式中，单个 `<`、`>` 归一化为 `\lt `、`\gt `，连续的 `<<` 与 `>>` 归一化为 LaTeX 标准关系符号 `\ll ` 与 `\gg `。

## 规则 15：解释性方括号与 Markdown 链接消歧

**问题**：中文论文中的段内注解（如 `[通常为 $\mathcal{N}(0, I)$ ]`）曾在 Obsidian 实时预览中出现链接着色、公式源码裸露。CommonMark 的快捷引用链接通常需要匹配的引用定义；单独出现方括号并不必然成为链接。应同时检查上下文、引用定义、插件及目标客户端。

**做法**：
- 正文中非超链接、非图片、非数字引用编号（如 `[1]`、`[29-30]`）的解释性方括号，只要其内部包含公式 `$..$` 或中文说明，在确认存在解析冲突且不改变原意后，可规范化为中文全角方括号 `［...］`；
- 全角方括号改变标点字形以避开链接语法；转换后再检查公式显示；引用编号、真实链接、代码和数学分组保持原样。

```markdown
<!-- 错误：半角方括号被 Obsidian 劫持为超链接，公式源码裸露为蓝色 -->
先验分布 $p(z)$ [通常为 $\mathcal{N}(0, I)$ ]。这种正则化...
不对称单元的原子信息[即 $M=(A_{\mathrm{asu}}, X_{\mathrm{asu}}, S, L)$ ，其中 $A_{\mathrm{asu}}$ ... L 为晶格参数]。

<!-- 已确认的修复：使用全角方括号，随后核验目标客户端 -->
先验分布 $p(z)$ ［通常为 $\mathcal{N}(0, I)$ ］。这种正则化...
不对称单元的原子信息［即 $M=(A_{\mathrm{asu}}, X_{\mathrm{asu}}, S, L)$ ，其中 $A_{\mathrm{asu}}$ ... L 为晶格参数］。
```

## 校验

归一化后抽取并编译全部公式，保留失败项供回源修复：

```bash
npm --prefix scripts install --ignore-scripts --no-audit --no-fund
python scripts/extract_formulas.py ./知识库 --out formulas.json
node scripts/validate_math.cjs formulas.json
```

交付前处理所有失败项。KaTeX 的 `throwOnError: true` 会把不支持的语法报告为异常；若原式依赖目标 MathJax 支持而 KaTeX 不支持的命令，核对原页和实际客户端后记录该差异，不要为了通过预检改坏原式。报告里 KaTeX 失败仍如实列为失败，即使目标端显示正常、差异也已记录，这样读报告的人才知道哪些公式依赖特定引擎。

注意校验时要把 `$$` / `$` 外壳剥掉再传给 KaTeX——它只接受纯公式内容，连着定界符传会报 "Can't use function '$' in math mode"。

括号计数仅生成疑点清单：简单剥离命令、分组或上下标会丢失结构信息，且合法的半开区间如 `[0,1)` 并不按同类括号配对。核对原页后再决定是否修复；括号配平既不说明语法正确，也不说明语义一致。最终在实际客户端核验，并对照来源检查变量、式号、单位和上下标。
