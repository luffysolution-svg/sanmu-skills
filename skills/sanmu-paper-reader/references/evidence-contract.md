# 证据与来源契约

此契约用于长期精读、跨文献比较和可更新的知识笔记。简单回答可直接提供等价的行内出处，无须为几句话建立文件体系。

## 来源主体与阅读定位

- Markdown/PDF/主文/SI是来源；解读笔记和用户批注不是论文已证实结论的替代来源。
- 来源清单 `schema_version: 1`，每条包含 `id`、`path`、`sha256`、`title`、`headings`。`inventory` 只发现 Markdown、文件哈希和标题，不理解DOI、文献版本、SI关系与物理页映射；这些由助手核对并记录于阅读笔记。
- 相对路径从显式指定的来源根目录算起，不能越界。标题变化不改变基于路径的ID；文件移动后需要重新核对关联。
- `sha256` 是源文件的字节哈希，换行变化也会使其变化。哈希变化应触发证据重读，不能只更新哈希后宣称语义不变。
- `locator` 记录人工/助手已核对的位置，例如“主文，PDF物理页7，§2.3，Fig.4f”。缺少页映射时用确实存在的章节和短引文，不伪造页码。
- `quote` 为可查找的原文短片段。工具只规范化空白；连字、上下标、负号不同不会自动视作相同。提取失真时回看 PDF，把未解决问题写入笔记，不能修改原始证据以迎合检查。

## JSON记录

下例只说明结构；`<...>` 处要换成实际读到的内容，原样留着的占位符不算证据。

```json
{
  "schema_version": 1,
  "evidence": [
    {
      "id": "E1",
      "claim": "作者在明确条件下报告的具体结果",
      "kind": "reported",
      "support": "supports",
      "source": {
        "path": "paper.md",
        "sha256": "<源文件SHA-256，64位十六进制>",
        "quote": "<正文中实际存在的短引文>",
        "locator": "<已核对的主文或SI、章节/页/图表>"
      },
      "measurements": [
        {
          "value": "<原文数值>",
          "unit": "<单位；无量纲写dimensionless>",
          "conditions": "<已读条件；未报告写not_reported并在笔记解释阅读范围>"
        }
      ]
    }
  ]
}
```

`kind` 的含义：`reported` 是作者报告的观察、计算或解释，不自动代表已独立验证；`interpretation` 是本次解读；`hypothesis` 是待验证假设。作者提出的机制也可能仅属推断，需在 `claim` 中写“作者推断”，不能因 `reported` 改写成已证明事实。

`support` 是此引文与此条论断的关系：`supports`、`contradicts` 或 `context`。一条来源支持不代表其他来源一致；同一论断可用多个不同ID连接不同来源，不能只保留支持材料。

`conditions` 还可写明“未获取SI”“尚未阅读相关方法”或“适用性待确认”；不要把这些状态都折叠为 `not_reported`。

`measurements` 可省略；若提供，每条都需要非空的 `value`、`unit`、`conditions`。字符串允许范围和不确定度，不能丢弃分母、归一化基准、参照电极、样本数或样品状态。工具不解析单位或检查换算是否科学正确。

## 输出位置与执行

```bash
python scripts/evidence_tools.py inventory ./sources --out ./work/sources.json
python scripts/evidence_tools.py check ./work/evidence.json --root ./sources --out ./work/check.json
```

先建立清单，再阅读并填写证据表。工具输出采用新文件；已有内容不同会拒绝覆盖，因此修订用明确的新版本文件名。无需额外Python依赖，不进行网络或模型调用。

## 验证分层

1. 机械检查：记录结构、路径边界、源文件哈希与正文引文存在。退出码0只表示这些检查通过。
2. 阅读核验：章节/页码/图号真实；引文上下文支持论断；主文与SI、测量和计算没有串用。
3. 科学评价：研究设计、对照、替代机制、统计与适用范围。检索覆盖范围、知识和工具的局限都要向用户说明，这一层校验脚本替代不了。

代码围栏和YAML元数据不算正文证据。文件中存在某个术语不等于支持某个因果论断。阅读核验发现的错误记录在笔记中，修订论断或补足来源后重检；原文存在内部矛盾时保留并列证据。
