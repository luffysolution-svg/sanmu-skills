# 扩展检索与更新协议

用户要求尽量查全、开题或综述时使用；日常找少量文献不强制生成这套产物。CLI 首版是有界检索工具，协议用于组合多次查询和标明覆盖，不声称具备全部数据库的系统检索实现。

检索前记录研究问题、对象/概念边界、具体时间窗、语言与文献类型、纳排条件、计划数据库、各库实际查询、分页/预算、种子与已知文献集。材料领域可以加入组成、反应、方法和测试条件，医学 PICO 不强加给所有课题。

以独立的已知文献集检查能否找回关键论文，不从当前结果中挑一组再宣布高召回。每篇遗漏追到查询、索引覆盖、时间过滤、标识符或解析问题；已知集合找回率的分母与来源一起报告。捕获-再捕获估计受来源独立性、收录偏好等假设影响，不作为默认查全评分。

## 执行顺序

1. 小样本检查各源响应、字段和查询语法，再按预算逐步扩大。确认需要的摘要、日期和稳定 ID 是否真实返回。
2. 每个源/查询独立记录成功、空结果、截断、失败与未执行。服务不可用就声明覆盖缺口，不能悄悄从计划删除。
3. 合并去重并保留原始记录和合并依据。标题相近、冲突或作者歧义进入待核查清单。
4. 标题/摘要筛选记录 `include_for_fulltext`、`exclude`、`uncertain` 和理由。明确符合预设排除条件者可在标题/摘要阶段排除，记录阶段与理由；最终纳入须全文资格核验。
5. 围绕已确认种子分别扩展参考和施引，记录轮次、新增、过滤与失败。失败轮和预算停止不计作“饱和”。
6. 全文资格需实际取得/阅读，并记录排除理由。PRISMA 只在阶段定义和计数能对账时生成；没有全流程数据就交阶段清单，不补造数字。

## 更新

新时间窗、查询或筛选标准使用新运行目录。用 `diff` 比较候选身份的新增、缺失和元数据变化；旧条目在某次查询中消失不等于撤稿。人工筛选结论只有身份与条件一致时才可迁移，机器初筛重新评价。运行文件变化会使哈希检查失败，修订时保留旧版本与修改说明。

## 报告口径

写清实际检索日期、覆盖区间、计划与执行来源、查询/预算、原始数与去重数、初筛状态、全文取得与未取得数、未执行内容和局限。逐项区分“分页执行完”“查询覆盖足够”“文献相关”“科学证据可靠”；任何一个程序状态不能代替其余判断。
